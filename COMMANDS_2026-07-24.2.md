## 6. Migration

Kör endast de nya/ersatta migrationerna genom normal Supabase-migrationsordning:

```bash
cd /Users/hekmath/Desktop/Projects/gridex-web
npx supabase db push --include-all
```

För en helt lokal tom utvecklingsdatabas kan hela historiken i stället verifieras med:

```bash
npx supabase db reset
```

Kör inte om redan applicerade migrationer manuellt mot produktion. `db push --include-all` applicerar endast migrationer som saknas i målprojektets migrationshistorik.

## 7. Staging-E2E

Kopiera `tests/fixtures/staging-ops-flow.example.json` till en lokal, git-ignorerad JSON-fixture och ersätt alla testvärden med godkända staginguppgifter. Kör sedan:

```bash
cd /Users/hekmath/Desktop/Projects/gridex-web
GRIDEX_API_KEY='gridex_test_xxxxxxxxx' \
GRIDEX_STAGING_E2E_FIXTURE='/Users/hekmath/Desktop/Projects/gridex-web/.local/gridex-staging-e2e.json' \
npm run test:staging:ops
```

Testet kör context → contracts → resolution → current market price → quote → validation → application två gånger → application status → portal bundle när `portal_user_id` finns.
